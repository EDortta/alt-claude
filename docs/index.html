O PROJETO CRESCEU

Não é mais só um seletor de backend.

O alt-claude agora cuida da escolha do modelo, dos limites de contexto, da recuperação de sessões e de quais rotas podem tocar cada projeto.

01

UM COMANDO

Perfis viraram a interface principal.

alt-claude --profile north-mini-code --yolo. Os antigos alt-claude-* continuam como atalhos de compatibilidade.

02

CONTEXTO

Não espere o modelo quebrar.

Cada perfil declara sua janela, uma margem segura e o ponto de compactação. Sessões grandes são bloqueadas antes de uma requisição condenada.

03

RECUPERAÇÃO

Compacte mesmo depois do limite.

alt-claude compact SESSION_ID lê o JSONL local e cria um handoff offline para começar uma sessão nova sem chamar outro modelo.

GUARDRAILS SEM ENGESSAR

O agente continua rápido.
O launcher fica atento.

O objetivo não é esconder o provider. É tornar explícitas as decisões que antes apareciam só quando algo quebrava.

01 / PERFIS

Modelos como configuração,
não scripts copiados.

Provider, modelo, contexto, margem segura, compactação e privacidade vivem no perfil. Todos herdam o mesmo parser e os mesmos parâmetros.

alt
north laguna nemotron
02 / CONTEXTO
SAFE

Margem antes do abismo.

North Mini Code, por exemplo, tem 256K de janela, mas o alt-claude corta o resume muito antes disso para reservar espaço para ferramentas e resposta.

03 / PROJETO
.alt-claude/↳ config policy↳ deny_provider ...

A pasta decide quem entra.

Um projeto pode bloquear providers, perfis ou classes de privacidade. A checagem acontece antes de qualquer chamada externa.

04 / COMPATIBILIDADE

--yolo e --resume em todo lugar.

Os parâmetros comuns passam pelo mesmo núcleo, independentemente do modelo escolhido.

--profile--yolo--resumecompactpolicy

PRIVACIDADE NÃO É UM ASTERISCO

Nem todo modelo gratuito deve ver todo código.

alt-claude profiles separa o catálogo por classe de privacidade. Se não há evidência suficiente, o perfil não ganha selo de seguro por otimismo.

A

SENSITIVE_OK

Adequado para projeto sensível.

Somente quando a política foi explicitamente verificada. Essa categoria não é presumida.

B

REVIEW

Revise antes de enviar código privado.

É a classe conservadora para endpoints e rotas cujos termos, retenção ou tratamento ainda exigem avaliação.

C

PUBLIC_ONLY

Somente código público ou descartável.

Inkling, Inkling Small e o roteador dinâmico openrouter/free ficam claramente separados nesta faixa.

PERGUNTAS QUE AGORA IMPORTAM

Antes que você
estoure outra janela.

Isso substitui o Claude Code?

Não. Claude Code continua sendo o harness. O alt-claude escolhe e governa as rotas por baixo dele.

O que acontece quando uma sessão fica grande demais?

O perfil tem um limite seguro. No resume, o alt-claude mede o JSONL local e pode bloquear antes que o provider devolva erro. Se já passou do ponto, use alt-claude compact SESSION_ID.

Posso impedir um modelo de tocar um repositório?

Sim. .alt-claude/config pode negar profiles, providers e classes de privacidade. A política é verificada antes da chamada externa.

Os modelos gratuitos são seguros para código privado?

Não assumimos isso. O catálogo separa sensitive_ok, review e public_only. O padrão é conservador.

Os antigos alt-claude-nemotron, alt-claude-laguna etc. sumiram?

Não. Continuam instalados como atalhos de compatibilidade, mas delegam para a interface unificada.
